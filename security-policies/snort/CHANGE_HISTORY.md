## 3. 변경 이력 관리 원칙

- 정책 변경 일자 및 담당자를 기록한다.
- 변경 사유와 변경 전·후 내용을 기록한다.
- 변경 요청 및 승인 관련 Issue, Pull Request를 연결한다.
- 정책 변경 전 백업 및 무결성 검사 결과를 기록한다.
- 운영 적용 전 후보 정책의 설정 유효성 검사를 수행한다.
- 담당자 검토 및 승인 이후 운영 정책에 반영한다.
- 변경 후 탐지 효과 및 정상 서비스 동작 검증 결과를 기록한다.
- 오탐 및 미탐 발생 여부와 정책 개선 필요성을 기록한다.
- 이전 정책으로 복구할 수 있도록 버전과 백업 파일을 관리한다.
- 운영 적용 및 재검증 완료 후 정식 정책 버전을 등록한다.

## 4. 비고

v1.0.0 최초 정책 등록 과정에서는 기존 운영 중인 Snort 탐지·차단 정책을 변경하지 않았다.

v1.1.0 신규 정책은 별도의 로컬 Git 작업 브랜치에서 작성하였으며, 기존 운영 환경에 영향을 주지 않도록 테스트용 설정 파일을 이용하여 사전 유효성 검사를 수행하였다.

현재 v1.1.0은 후보 정책 상태이며, 변경 승인 및 운영 적용 이후 실제 탐지 효과와 정상 서비스 동작 여부를 검증할 예정이다.

실제 운영 정책 파일과 백업은 IPS 인스턴스 내 접근이 제한된 관리 디렉터리에 보관하며, GitHub에는 정책 변경 이력 및 승인·검토 결과를 기록한다. 상세 탐지 조건과 내부 네트워크 정보는 공개하지 않는다.

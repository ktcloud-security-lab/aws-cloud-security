### 2.5 탐지 정책 검증 결과

신규 탐지 정책의 동작 여부를 확인하기 위해 Scapy 기반 테스트용 PCAP 파일과 Snort 오프라인 분석 환경을 구성하였다.

운영 네트워크에 실제 테스트 패킷을 전송하지 않고 별도의 PCAP 분석을 수행하여 다음과 같은 검증 결과를 확보하였다.

| 검증 대상 | 결과 |
|---|---|
| NULL Scan 의심 탐지 | Alert 발생 확인 |
| FIN Scan 의심 탐지 | Alert 발생 확인 |
| XMAS Scan 의심 탐지 | Alert 발생 확인 |
| LAND Attack 의심 탐지 | Alert 발생 확인 |
| ACK Scan 의심 탐지 | 후속 검증 필요 |

또한 PCAP 기반 탐지 정책 자동 분석 스크립트를 구성하여 향후 신규 정책 추가 및 변경 시 반복적인 탐지 검증을 수행할 수 있도록 하였다.

신규 탐지 정책 7개 중 4개에 대한 오프라인 탐지 검증을 완료하였으며, 나머지 임계값 기반 탐지 정책 3개는 검증용 데이터 확보 후 추가 검증을 수행할 예정이다.

※ 본 검증은 개별 룰의 오프라인 탐지 기능을 확인한 것으로, 실제 운영 환경의 전체 공격 탐지율이나 인라인 차단 효과를 의미하지 않는다.

### 2.6 정책 운영 및 개선 방향

신규 정책은 네트워크 기반 유해 트래픽 탐지 범위를 확대하기 위해 추가하였으며, 정상 서비스에 대한 영향을 최소화하기 위해 Alert 방식으로 운영한다.

실제 운영 로그, 탐지 정확성 및 오탐 가능성을 검토한 후 차단 정책 전환 여부를 결정한다.

임계값 기반 탐지 정책의 추가 검증과 정상 트래픽에 대한 오탐 검토는 후속 개선 사항으로 관리한다.

## 4. 보안 정책 파일 관리

실제 운영 중인 Snort 설정 파일 및 탐지 룰은 IPS 인스턴스의 접근이 제한된 로컬 Git 저장소에서 관리한다.

GitHub에서는 정책 관리대장, 변경 요청, 승인 및 검토 이력을 관리하며, 상세 탐지 조건과 내부 네트워크 정보는 공개하지 않는다.

정책 변경 시 별도의 작업 브랜치를 사용하는 것을 원칙으로 하며, 설정 유효성 검사 및 변경 승인 절차를 거쳐 운영 환경에 적용한다.

v1.1.0 정책 변경 과정에서는 로컬 Git main 브랜치에 직접 커밋하였으며, 운영 정책 파일과 Git 관리 파일이 일치하는 것을 확인하였다. 향후 정책 변경 시에는 작업 브랜치 생성 및 병합 절차를 준수하도록 한다.

현재 운영 정책은 v1.1.0 태그를 통해 관리하며, 변경 이력 및 후속 검증 결과를 지속적으로 기록한다.

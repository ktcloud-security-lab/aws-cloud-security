# 벤더 보안 권고 및 대응 관리

## 1. 관리 목적

보안장비 및 운영체제 제조사의 보안 권고, 신규 취약점, 보안 패치 및 기술 지원 종료 정보를 주기적으로 확인하고 대응한다.

## 2. 공식 정보 확인 경로

| 벤더 | 확인 대상 | 공식 정보 경로 |
|---|---|---|
| Canonical | Ubuntu 보안 업데이트 및 취약점 | https://ubuntu.com/security/notices |
| Cisco Snort | Snort 엔진 및 공식 탐지 룰 | https://www.snort.org/ |
| Cisco Talos | 신규 위협 및 보안 권고 | https://talosintelligence.com/ |
| AWS | AWS 서비스 보안 공지 | https://aws.amazon.com/security/security-bulletins/ |
| AWS WAF | 관리형 규칙 변경 사항 | https://docs.aws.amazon.com/waf/ |

## 3. 최초 벤더 권고 점검

- 점검 일자: 2026-11-25
- 점검 대상: Ubuntu, Snort IPS, AWS WAF

| 대상 | 확인 사항 | 대응 방향 |
|---|---|---|
| Ubuntu | 자동 보안 업데이트 적용 | 기존 자동 업데이트 유지 |
| Snort 2.9.20 | 벤더 지원 상태 및 엔진 갱신 필요성 | 지원 버전 전환 검토 |
| Snort 공식 탐지 룰 | 정기 갱신 체계 미흡 | 지원되는 룰 갱신 방식 검토 |
| AWS WAF | 관리형 규칙 기본 버전 사용 | 기존 설정 유지 |

## 4. Snort 엔진 개선 계획

현재 운영 중인 Snort 엔진에 대해 제조사의 기술 지원 상태를 확인하고, 지원되는 Snort 버전으로 전환하기 위한 검토를 수행한다.

- 지원 버전 및 공식 탐지 룰 확인
- 별도 테스트 환경 구축
- 기존 탐지·차단 룰 호환성 검증
- NFQUEUE 인라인 동작 검증
- 설정 및 정책 백업
- 서비스 영향도 분석
- 팀원 검토 및 승인
- 운영 환경 전환 및 정상 동작 검증

## 5. 미조치 사항 관리

현재 IPS는 전체 인프라의 패킷 검사 및 전달 경로에 위치하고 있으므로 엔진 교체 및 시스템 재부팅에 따른 서비스 중단 가능성이 존재한다.

이에 따라 운영 중인 환경의 즉각적인 엔진 교체는 보류하고, 사전 호환성 검증 및 팀원 협의 이후 전환한다.

실제 패치 및 엔진 전환이 완료되기 전까지 해당 사항을 잔여 개선 대상으로 관리한다.

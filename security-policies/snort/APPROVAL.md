## 3. 승인 관리 원칙

정책 변경 요청은 GitHub Issue를 통해 관리하며, 변경 내용은 Pull Request를 통해 검토한다.

담당 팀원의 검토 및 승인 이후 정책을 적용하고, 승인 결과와 검증 결과를 변경 이력에 기록한다.

승인되지 않은 정책은 운영 환경에 적용하지 않는 것을 원칙으로 한다.

정책 변경 전에는 기존 정책에 대한 백업 및 무결성 검사를 수행하고, 후보 정책의 설정 유효성을 검증한다.

운영 적용 이후에는 Snort IPS 서비스 상태, 정상 서비스 동작 여부 및 변경된 정책의 탐지·차단 기능을 검증한다.

미검증 항목 및 잔여 개선 사항은 별도로 기록하며, 승인 여부와 운영 적용 여부는 구분하여 관리한다.

## 6. 정책 변경 관리 개선 사항

| 개선 항목 | 개선 방향 |
|---|---|
| 사전 승인 관리 | 운영 정책 적용 전 팀원 검토 및 승인 기록 확보 |
| 변경 요청 관리 | GitHub Issue와 Pull Request 연결 |
| Git 브랜치 관리 | 별도의 작업 브랜치 생성 및 검토 후 병합 |
| 탐지 검증 관리 | 신규 정책별 탐지 결과 및 미검증 항목 기록 |
| 오탐 관리 | 실제 운영 로그 기반 탐지 적정성 검토 |
| 차단 정책 관리 | 차단 전환 전 서비스 영향도 검토 및 승인 |

v1.1.0 변경 과정에서는 로컬 Git main 브랜치에 직접 커밋하였으며, 별도의 작업 브랜치 생성 및 병합 절차는 완료되지 않았다.

향후 정책 변경 시에는 수립된 변경 요청, 검토, 승인 및 브랜치 관리 절차를 준수하도록 한다.

## 7. 비고

현재 Snort IPS 운영 정책은 v1.1.0으로 관리하고 있으며, 변경 전 정책인 v1.0.0은 로컬 Git 버전관리 및 백업을 통해 보관하고 있다.

정책 변경 관련 승인 및 재검증 결과는 APPROVAL.md, CHANGE_HISTORY.md, REVIEW.md에 지속적으로 기록한다.

실제 운영 정책 파일과 상세 탐지 조건은 IPS 인스턴스 내 접근이 제한된 로컬 Git 저장소에서 관리하며, 공개 GitHub 저장소에는 정책 관리 및 승인에 필요한 정보만 등록한다.

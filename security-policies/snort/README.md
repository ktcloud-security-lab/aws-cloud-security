- Snort 탐지·차단 정책 버전관리
- 정책 변경 요청 및 승인 이력 관리
- 정책 정기 적정성 검토
- 정책 백업 및 복구 절차 관리
- 정책 변경 후 정상 동작 검증
- 보안 패치 및 벤더 권고 관리
- 탐지 정확성 및 오탐·미탐 검토

## 4. 현재 운영 정책 현황

| 구분 | 정책 개수 |
|---|---:|
| 탐지 정책(Alert) | 10개 |
| 차단 정책(Drop) | 1개 |
| 전체 사용자 정의 정책 | 11개 |

※ 사용자 정의 룰의 기본 Action 기준이며, 기존 rate_filter 기반 조건부 차단 정책은 별도로 유지한다.

### 신규 탐지 정책 검증 현황

| 탐지 유형 | 운영 적용 | 오프라인 탐지 검증 |
|---|---|---|
| NULL Scan | 완료 | 성공 |
| FIN Scan | 완료 | 성공 |
| XMAS Scan | 완료 | 성공 |
| ACK Scan | 완료 | 후속 검증 필요 |
| UDP Flood | 완료 | 후속 검증 필요 |
| ICMP Flood | 완료 | 후속 검증 필요 |
| LAND Attack | 완료 | 성공 |

신규 탐지 정책 7개를 운영 환경에 적용하였으며, 4개 정책의 오프라인 탐지 검증을 완료하였다.

정책 변경 이후 Snort IPS 서비스 정상 실행, NFQUEUE 인라인 구성 유지 및 웹 서비스 HTTPS 정상 응답을 확인하였다.

나머지 3개 탐지 정책의 임계값 검증과 정상 트래픽에 대한 오탐 검토는 후속 개선 사항으로 관리한다.

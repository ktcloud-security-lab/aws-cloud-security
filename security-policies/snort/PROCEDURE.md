# Snort IPS 정책 관리 절차

## 1. 관리 목적

보안 정책의 무단 변경을 방지하고 변경 이력, 승인 및 검증 결과를 체계적으로 관리한다.

## 2. 정책 변경 절차

| 단계 | 수행 내용 |
|---|---|
| 1. 변경 요청 | GitHub Issue를 통해 변경 목적, 사유 및 대상 정책 등록 |
| 2. 영향도 분석 | 정상 서비스 영향, 오탐 및 미탐 가능성 검토 |
| 3. 정책 백업 | 기존 설정 및 탐지·차단 룰 백업 |
| 4. 변경안 작성 | 변경 예정 정책 및 변경 사유 작성 |
| 5. 사전 검증 | Snort 설정 유효성 검사 및 변경안 검증 |
| 6. 변경 검토 및 승인 | Pull Request를 통해 팀원 검토 및 승인 |
| 7. 정책 적용 | 승인된 정책을 운영 환경에 적용 |
| 8. 정상 동작 검증 | Snort 실행 상태, 탐지 기능 및 서비스 정상 동작 확인 |
| 9. 이력 관리 | Git 버전, 변경 담당자, 승인자 및 검증 결과 기록 |

## 3. 정책 복구 절차

정책 변경 이후 장애 또는 오탐이 발생할 경우 이전에 백업한 정책 또는 검증된 Git 버전을 이용하여 복구한다.

복구 후 Snort 설정 유효성 및 서비스 정상 동작 여부를 확인하고 복구 이력을 기록한다.

## 4. 정기 검토

- 검토 주기: 월 1회
- 수시 검토: 신규 위협, 오탐·미탐 및 정책 변경 발생 시
- 검토 대상: 중복 정책, 불필요 정책, 탐지 정확성 및 운영 필요성
- 검토 결과: REVIEW.md에 기록
- 정책 변경이 필요한 경우 변경 요청 및 승인 절차에 따라 수행

## 5. 보안 관리

실제 운영 정책 및 상세 네트워크 정보는 접근이 제한된 로컬 정책 저장소에서 관리한다. 공개 GitHub 저장소에는 민감정보를 제외한 정책 관리 문서와 변경·승인 이력만 등록한다.


# AWS Access Control Policy Management

## 1. 목적

404팀 AWS 클라우드 환경의 접근 제어 정책을 체계적으로 관리하고,
불필요한 접근 허용 규칙 및 과도한 권한을 정기적으로 검토한다.

## 2. 관리 범위

- AWS Security Group (SG)
- Network ACL (NACL)
- AWS IAM 사용자 및 그룹 권한
- AWS Systems Manager 원격 관리 접근 권한
- NAT 및 IPS 호스트 방화벽 정책

## 3. 관리 원칙

- 최소 권한 원칙 적용
- 직무 기반 접근통제(RBAC)
- 태그 기반 접근통제(ABAC)
- 필수 서비스 통신만 허용
- 불필요한 외부 및 내부 접근 제한
- 운영상 예외 정책의 허용 사유 기록
- 정책 변경 전 영향도 검토 및 승인
- 정책 변경 후 정상 동작 및 접근통제 재검증

## 4. 정기 검토 기준

| 구분 | 관리 기준 |
|---|---|
| 정기 검토 | 월 1회 |
| 수시 검토 | 인프라 및 권한 변경, 보안사고 발생 시 |
| 검토 담당 | 네트워크 담당자 및 보안 담당자 |
| 승인 담당 | 프로젝트 총괄 관리자 |
| 검토 대상 | SG, NACL, IAM, 호스트 방화벽 |
| 검토 기록 | REVIEW.md |
| 정책 관리대장 | POLICY_INVENTORY.md |

## 5. 정책 변경 관리 절차

1. 기존 접근 제어 정책 확인
2. 불필요하거나 과도한 접근 권한 식별
3. 변경 요청 및 영향도 검토
4. 담당자 검토 및 관리자 승인
5. 접근 제어 정책 변경
6. 정상 서비스 및 접근 제한 재검증
7. 정책 관리대장 및 검토 이력 갱신

정책 변경 요청 및 관리 문서의 검토·승인 이력은
GitHub Issue 및 Pull Request를 활용하여 관리한다.

## 7. 관련 취약점 점검 항목

- S-06: 원격 관리 접근 통제
- S-18: 최소한의 서비스만 제공
- CA-05: 인스턴스 서비스 정책 관리
- CA-06: 네트워크 서비스 정책 관리
- CA-09: 접근 제어 설정 관리

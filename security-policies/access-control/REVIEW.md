### 3. 내부 네트워크 접근통제 재검증

WAS 및 DB 서브넷에 전용 NACL을 적용한 이후
AWS Systems Manager를 통해 각 인스턴스에 접속하여
필수 서비스 연결 및 불필요한 직접 접근 차단 여부를 검증하였다.

| 출발지 | 목적지 | 포트 | 기대 결과 | 실제 결과 | 판정 |
|---|---|---|---|---|---|
| WEB | WAS | TCP 8000 | 허용 | 연결 성공 | PASS |
| WEB | DB | TCP 3306 | 차단 | 연결 시간 초과 | PASS |
| WAS | DB | TCP 3306 | 허용 | 연결 성공 | PASS |
| WAS | 외부 인터넷 | TCP 443 | 허용 | NAT 공인 IP 확인 | PASS |
| DB | 외부 인터넷 | TCP 443 | 허용 | NAT 공인 IP 확인 | PASS |

검증 대상 5개 항목에서 기대 결과와 동일한 결과를 확인하였다.

이를 통해 필수 서비스 통신이 정상적으로 유지되며
WEB에서 DB로의 직접 접근이 제한되고 있음을 확인하였다.

### 4. 운영상 예외 정책 검토

| 대상 | 검토 내용 | 후속 관리 |
|---|---|---|
| IPS 내부 전체 허용 | 인라인 패킷 전달 목적의 운영상 예외 | 필수 통신 범위 정기 검토 |
| NAT HTTP·HTTPS 허용 | 외부 웹 트래픽 전달 목적 | 기존 전달 정책 유지 및 검토 |
| NAT·IPS 아웃바운드 전체 허용 | 패킷 전달 및 서비스 운영 목적 | 세분화 가능 여부 검토 |
| IAM 서비스별 FullAccess | 직무별 네트워크 관리 목적 | 리소스 단위 권한 최소화 검토 |

운영상 예외 정책에 대해서는 허용 목적과 보완 통제를
정책 관리대장에 기록하고 향후 정기 검토 대상으로 관리한다.

### 5. 검토 결과

- SG 기반 계층별 접근 제어 구성 확인
- WAS 및 DB 전용 NACL 적용 확인
- 내부 서비스 통신 및 접근 제한 재검증 성공
- NAT 기반 외부 HTTPS 통신 정상 확인
- 직무별 IAM 접근 제어 개선 확인
- 접근 제어 정책 관리대장 작성
- 월 1회 정기 검토 기준 수립

네트워크 및 IAM 기반 접근 제어 정책을 개선하고,
필수 서비스 통신과 불필요한 직접 접근 제한 여부를
기술적으로 검증하였다.
